## Estrategia de Ramas
Utilizamos **GitFlow** simplificado:
* `main`: Codigo estable en produccion.
* `develop`: Rama de integracion para desarrollo.
* `feature/nombre-tarea`: Ramas temporales para nuevas funcionalidades.

## Politica de Pull Requests
1. Toda PR debe ser revisada por al menos 1 compañero.
2. Debe pasar los tests automaticos (si aplica).
3. No se permite el merge directo a `main`.
